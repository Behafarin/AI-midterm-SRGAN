# Applied AI Mid-Term: SRGAN for Dog vs. Cat Classification

**Behafarin (Behi) Emam** · UNCC ID: `bemam`

This project trains a **Super-Resolution GAN** ([Ledig et al., 2017](https://arxiv.org/pdf/1609.04802.pdf)) that rebuilds **128×128** images from **32×32** inputs. It then compares two Dogs-vs-Cats classifiers:

| Model | Trained on |
|---|---|
| **A** | real 128×128 photos (same transfer-learning recipe as Assignment 1) |
| **B** | 128×128 images generated by the SRGAN from 32×32 inputs |

**Main result.** Model B, trained only on SRGAN images, reaches **97.3%** accuracy on *real* test photos. That is the same as Model A (97.4%). When a model is given SRGAN images instead of real ones, accuracy drops to about **94.4%**, for either model. So the cost of working from 32×32 comes from the information lost when shrinking the images, not from training on generated images. The SRGAN also beats plain bicubic upscaling by **5–7 accuracy points** as a preprocessing step.

## 2. How to reproduce

Requirements: Linux, Python 3.11, and [uv](https://docs.astral.sh/uv/). An NVIDIA GPU is recommended (see §11).

```bash
# 1. Kaggle API token (kaggle.com -> Settings -> API -> Create New Token)
mkdir -p ~/.kaggle && mv kaggle.json ~/.kaggle/ && chmod 600 ~/.kaggle/kaggle.json

# 2. Environment (creates .venv with uv, installs packages, runs check_setup.py)
bash setup.sh

# 3. Optional 5-minute bug check: 1-2 epochs of everything, then delete its outputs
SMOKE_TEST=1 bash run_all.sh && rm -rf outputs report_executed.ipynb

# 4. The full run, inside tmux so it survives disconnection
tmux new -s midterm
source .venv/bin/activate
CUDA_VISIBLE_DEVICES=0 bash run_all.sh        # detach: Ctrl+b then d
```

`run_all.sh` runs the seven stages below in order. It writes `outputs/logs/<stage>.done` when a stage finishes and skips finished stages on later runs. If the run is interrupted, run the same command again: training continues from the last saved checkpoint (§10). To run a single stage, pass its tag, e.g. `bash run_all.sh 03_srgan`.

| Tag | Script | Produces |
|---|---|---|
| `01_prepare` | `src/01_prepare_data.py` | resized image cache, split table, figures 01–03 |
| `02_model_A` | `src/02_train_classifier.py --model A` | `models/model_A_final.keras` |
| `03_srgan` | `src/03_train_srgan.py` | `models/srgan_generator_final.keras` |
| `04_eval_sr` | `src/04_evaluate_srgan.py` | figures 04–05, `sr_quality_test.csv` |
| `05_gen_sr` | `src/05_generate_sr_dataset.py` | SRGAN dataset, figure 06 |
| `06_model_B` | `src/02_train_classifier.py --model B` | `models/model_B_final.keras` |
| `07_compare` | `src/07_compare_models.py` | `model_comparison.csv`, figures 07–09 |

When all stages finish, `run_all.sh` runs `report.ipynb`, which displays every figure and table inside a Jupyter notebook (`report_executed.ipynb`).

The random seed is fixed to **42** everywhere: the split, shuffling, weight initialization and the SRGAN subset.

## 3. Step 1: Dataset and 70/30 split

- **Dataset:** [Dogs vs. Cats Classification](https://www.kaggle.com/datasets/blourdhuraju/dogs-vs-cats-classification) on Kaggle, the same one used in Assignment 1. It is downloaded automatically with `kaggle datasets download -d blourdhuraju/dogs-vs-cats-classification`.
- **Labels:** each image's label is taken from its folder or file name. This gives **24,930** labeled images: **12,472 cats** and **12,458 dogs**. All of them were readable.
- **Resizing:** every image is converted to RGB and resized **once** to **128×128** (bicubic). The result is cached as `uint8` arrays.
- **Split:** a **stratified 70% / 30%** split, so cats and dogs keep the same ratio in both parts. Another 10% of the training part is held out as a **validation set**, used for early stopping and for watching the SRGAN's progress.
- **The 30% test set is never used for training,** neither by the classifiers nor by the SRGAN.

| Split | Cats | Dogs | Total |
|---|---|---|---|
| Train (70%) | 8,730 | 8,721 | 17,451 |
| ↳ used for fitting | 7,857 | 7,848 | 15,705 |
| ↳ validation (10% of train) | 873 | 873 | 1,746 |
| **Test (30%)** | **3,742** | **3,737** | **7,479** |

The exact file list of each split is saved in `outputs/results/split_train_files.csv` and `split_test_files.csv`.

## 4. Step 2: Scaled images, normalization and transformations

### Downscaling to 32×32

To create the SRGAN's inputs, each 128×128 image is shrunk 4× to 32×32 using bicubic resizing with anti-aliasing. This is the same degradation used in the SRGAN paper. The 32×32 images keep only 1/16 of the pixels.

![Scaled examples](outputs/figures/01_scaled_examples.png)
*Top: 128×128 test images. Bottom: the 32×32 versions the SRGAN receives (enlarged with nearest-neighbour so the real pixels are visible).*

### Transformations (classifiers, training batches only)

Each training batch gets new random transformations every epoch. Validation and test images are never transformed.

| Transformation | Setting |
|---|---|
| Horizontal flip | random |
| Rotation | ±20° |
| Zoom | ±15% |
| Translation | ±10% horizontal and vertical |
| Brightness | ±20% |

![Augmentations](outputs/figures/02_augmentations.png)

### Normalization

- **Classifiers:** a `Rescaling(1/127.5, offset=-1)` layer **inside the model** maps pixels from `[0, 255]` to `[-1, 1]`, which is the range MobileNetV2's ImageNet weights expect. Because the layer is part of the model, the saved model normalizes its own inputs. On a sample batch, the values went from min 0 / max 255 / mean 110.5 to min −1.00 / max 1.00 / mean −0.13.
- **SRGAN:** following the paper, 32×32 inputs are scaled to `[0, 1]` and 128×128 targets to `[-1, 1]` (the generator ends in `tanh`). Each training pair is also flipped horizontally at random.

![Normalization](outputs/figures/03_normalization.png)

## 5. Step 3: Model A (real 128×128 images)

This is the same transfer-learning recipe as Assignment 1, where **MobileNetV2** was the best backbone. MobileNetV2 has ImageNet weights for 128×128 inputs, so it is used directly at the exam resolution.

- **Architecture:** `Rescaling → MobileNetV2 (ImageNet, frozen) → GlobalAveragePooling → Dense(128, ReLU) → Dropout(0.3) → Dense(1, sigmoid)`
- **Stage 1 (head training):** only the new head is trained; the backbone stays frozen. Adam with learning rate `1e-3`, up to 8 epochs.
- **Stage 2 (fine-tuning):** the last 30 backbone layers are unfrozen. Adam with learning rate `1e-5`, up to 6 epochs.
- **Both stages:** binary cross-entropy loss, batch size 32, `EarlyStopping(patience=3, restore_best_weights=True)`, `ReduceLROnPlateau(factor=0.5, patience=2)`.

![Model A training curves](outputs/figures/model_A_training_curves.png)

Model A reached **98.2% validation accuracy** after head training and **98.3%** during fine-tuning. Training accuracy is lower than validation accuracy because training images are augmented and the head uses dropout.

## 6. Step 4: SRGAN

### Architecture (as in the paper)

- **Generator** (1.55 M parameters): `Conv 9×9 (64) + PReLU` → **16 residual blocks** (`Conv 3×3 → BatchNorm → PReLU → Conv 3×3 → BatchNorm` + skip connection) → `Conv → BatchNorm` + long skip connection → **two sub-pixel (PixelShuffle) ×2 upsampling blocks** (32 → 64 → 128) → `Conv 9×9 (3) + tanh`.
- **Discriminator** (38.2 M parameters): 8 convolution layers (64 → 512 filters, alternating stride 1 and 2) with BatchNorm and LeakyReLU(0.2) → `Dense(1024)` → `Dense(1)`, which outputs a real/fake score.

### Losses

- **Content loss:** mean squared error between the **VGG19 `block5_conv4`** feature maps of the generated and real images (the paper's "VGG54" loss), scaled by 1/12.75.
- **Adversarial loss:** binary cross-entropy that rewards the generator when the discriminator calls its output real.
- **Generator loss** = content loss + **10⁻³** × adversarial loss. The **discriminator loss** is binary cross-entropy on real vs. generated images.

### Training

| Setting | Value |
|---|---|
| Warm-up | 10 epochs training the generator alone with pixel MSE (the paper starts SRGAN from a trained SRResNet). MSE fell from 0.0335 to 0.0121. |
| Adversarial training | **150 epochs** |
| Images per epoch | all 15,705 training images, batch size 16 (981 steps per epoch) |
| Optimizer | Adam (β₁ = 0.9), learning rate `1e-4` for epochs 1–75, then `1e-5` for epochs 76–150 |
| Checkpoints | every 5 epochs (see §10), with a sample image grid saved each time to `outputs/figures/srgan_progress/` |

### Training curves

![SRGAN losses](outputs/figures/04_srgan_losses.png)

- The **content loss fell steadily**, from 0.317 at epoch 1 to about 0.13 at epoch 75. It then **dropped sharply when the learning rate decreased** at epoch 76, and ended at **0.113** at epoch 150.
- The **discriminator learned to separate real from generated images very quickly**. Its accuracy rose above 98% within 10 epochs, and to about 99.5–100% after the learning-rate drop. From then on the adversarial loss stayed high (about 11–12), which means the discriminator always won. In practice, most of the generator's improvement came from the VGG content loss rather than from the adversarial signal. This is a known SRGAN behavior (see §9).

### Results on unseen test images

![SRGAN test examples](outputs/figures/05_srgan_test_examples.png)
*Rows, top to bottom: the 32×32 input, bicubic upscaling, the SRGAN output, and the original 128×128 image.*

The SRGAN images are **much sharper than bicubic**. Fur texture, eyes, whiskers and edges are restored, while bicubic stays blurry. The SRGAN sometimes **invents details** that are not in the original. For example, in the last column it replaced the patterned background with a different texture.

| Test set (7,479 images) | PSNR (dB) ↑ | SSIM ↑ |
|---|---|---|
| Bicubic | **25.06** | **0.708** |
| SRGAN | 23.88 | 0.658 |

Bicubic scores higher on PSNR and SSIM even though it looks blurrier. These metrics compare images pixel by pixel, and they reward safe, blurry guesses over sharp details placed in slightly wrong positions. The SRGAN paper reports the same effect: its images have lower PSNR than plain MSE-trained models but are preferred by human viewers. The classifier results in §8 show that the SRGAN's sharper details are the ones that matter for recognition.

## 7. Step 5: SRGAN dataset and Model B

After training, every image in the training, validation and test sets is shrunk to 32×32 and passed through the trained generator. This creates a second 128×128 dataset made **only of SRGAN outputs**, with the same labels and the same split. Generating all 24,930 images took about 2 minutes.

![Model B training images](outputs/figures/06_model_B_training_images.png)
*Top: training images for Model A (real). Bottom: the same images as Model B sees them (SRGAN reconstructions from 32×32).*

**Model B** uses **exactly** Model A's architecture, hyperparameters, transformations and normalization. The only difference is the training data.

![Model B training curves](outputs/figures/model_B_training_curves.png)

Model B reached about **96% validation accuracy** on SRGAN images. This is lower than Model A's 98% on real images, because the SRGAN images carry less information.

## 8. Step 6: Comparing Model A and Model B

Both models are evaluated on the same 30% test set (7,479 images, which neither model nor the SRGAN has seen), in three versions:

- **real 128×128:** the original photos
- **SRGAN 128×128:** test photos shrunk to 32×32 and rebuilt by the SRGAN
- **bicubic 128×128:** test photos shrunk to 32×32 and enlarged with plain bicubic (no learning)

The positive class is *dog*. AUC is the area under the ROC curve.

### Main comparison: each model on the kind of images it was trained on

## 9. Discussion

**1. Model A vs. Model B.** Model A on real images beats Model B on SRGAN images by **2.95 accuracy points** (97.35% vs. 94.40%), **0.029 F1** and **0.007 AUC**. This is the cost of starting from 32×32 inputs, which keep only 1/16 of the pixels. Getting within 3 points of the full-resolution model, with an AUC still above 0.99, shows that the SRGAN keeps most of the information needed to tell cats from dogs.

**2. The drop comes from the test images, not from the model.** The other rows of the table show this clearly:
- Model B tested on **real** photos scores **97.29%**, essentially the same as Model A (97.35%), even though Model B never saw a real photo during training.
- Model A tested on **SRGAN** images scores **94.34%**, essentially the same as Model B (94.40%).

So training on generated images did not make the classifier worse. Both models perform the same on the same images, and accuracy depends almost entirely on whether the *test* image is real or rebuilt from 32×32. The limit is the information lost when the image is shrunk, which no upscaling method can fully recover.

**3. SRGAN vs. bicubic.** On bicubic-upscaled images, Model A drops to **87.6%** and Model B to **89.0%**. That is 5–7 points below their scores on SRGAN images, with AUC about 0.03 lower. Bicubic images also make Model A biased: it calls many blurry dogs "cat" (dog recall 0.795). So the SRGAN restores details that matter for recognition, even though bicubic scores higher on PSNR/SSIM (§6). For a classification task, perceptual sharpness matters more than pixel-level accuracy. Model B handles bicubic images a little better than Model A, probably because it was trained on images that are not perfect photos.

**4. SRGAN training behavior.** The discriminator won early and almost completely: its accuracy was ~99.5–100% after the learning-rate drop at epoch 76. That left the generator with little useful adversarial feedback, so most of its learning came from the VGG content loss. The images are sharp anyway, because the VGG loss already favors realistic texture. Ways to balance the two networks in future work include:
- label smoothing
- a lower discriminator learning rate
- a relativistic discriminator (as in ESRGAN)

**5. Limitations.**
- Single run with one seed (42), so there are no error bars.
- The SRGAN sometimes invents textures (the backgrounds in §6).
- Model B reuses Model A's hyperparameters, which were tuned on real images in Assignment 1.
- MobileNetV2's ImageNet pre-training probably helps both models tolerate imperfect inputs.

## 10. Saving models during training

Every expensive step saves its progress, so a crash or shutdown loses at most a few epochs.

| Stage | What is saved, and when | On re-run |
|---|---|---|
| Image cache | resized arrays and SRGAN dataset, as `.npy` | loaded; not recomputed |
| Classifiers A / B | Keras `BackupAndRestore` after **every epoch**, a `.keras` checkpoint after **every epoch**, the best model by validation loss, and each finished stage in `models/` | resumes mid-stage, or skips a finished stage |
| SRGAN | a full `tf.train.Checkpoint` **every 5 epochs** (generator, discriminator, both optimizers, epoch counters; last 3 kept), plus `models/srgan_generator_latest.keras` and a sample image grid | resumes from the last checkpoint |

This was used in practice. The run was stopped on purpose after the epoch-145 checkpoint so the server could be shut down. On restart, the log shows `RESUMED from .../ckpt-31: pre-train epoch 10, adversarial epoch 145`, and training finished the last 5 epochs.

Every stage also saves:
- its own log file (`outputs/logs/<stage>.log`)
- per-epoch metrics as CSV (`outputs/results/*_log.csv`)
- the exact configuration it ran with (`outputs/results/config_<stage>.json`)
